# OLED：Codex 任务页与 VIA 按键显示

## 当前源码与实机

当前源码 `0.4.9-qmk` 将 OLED 与宿主关灯状态分离：任务灯全灭不再关屏，无任务灯分配时保留 Logo+CODEX；进入 Codex 从首个可显示帧起展示完整约 1 秒 Logo。有任务时保留原六格任务页和色类推断。63 项固件离线检查通过，流水线版本已刷入，版本/切层状态核验及用户入层 Logo 目视确认通过；用户选择跳过一小时息屏/按键唤醒，不能将其记为实测通过。测试步骤见 [使用与刷写](usage.md)。当前固件合成展示见 [README](../README.md#小屏幕展示)，不是实机照片。

协议未传明确任务状态，标签仅是灯色估计：蓝色可推断 RUN，红色可推断 ERR，但红色品牌预览也会显示 ERR；宿主用紫色表示运行时会显示 OTHR。不能把标签当成已验证的业务状态，也不能只凭颜色区分录音/其他提示。亮度为 0 不代表无任务；只有未分配或明确 off 显示 --，全黑基色也可能配合有效动画发光。具体分类阈值和限制见 `lighting.md`。

## 留边与切层

### 冷启动等待页（0.4.8-qmk，0.4.7 起移除 DOIO 页）

- 删除 DOIO 的板级五秒 Logo 展示，`OLED_LOGO_TIMEOUT=0` 使其从首帧就委托本 keymap，不是仅覆盖五秒后的用户画面。
- 冷启动十秒协商期居中显示原文 `VIA WAITTING`（按用户拼写，未改成 WAITING），仍保留左右 6 px、上下 4 px 安全边距。
- 有效 VIA 命令锁定身份后，等待页结束，恢复层号/实际按键页；没有命令则十秒后复位进入 Codex，保留 Logo+CODEX 和任务页，不显示 DOIO。
- 使用实际模式等待状态，不另起 OLED 计时；复位或刚刷完可能保留 Codex 模式，需要断电上电才能观察完整冷启动流程。单次刷写成功或 RPC 版本应答不能代替屏幕目视验收。

`0.4.9-qmk` 修复旧共享关灯判断先于 Logo 绘制造成的黑屏。`poc_power.c` 仍提供统一的一小时活动时钟，但 OLED 仅检查 USB 挂起/一小时无输入且无有效通信；RGB 额外保留 Codex 聚合灯态关灯条件。全部任务/环境 off、亮度 0 或黑色不会再关闭 OLED；协议没有独立 OLED 关屏命令。有效心跳与重复内容照常续时，允许恢复时即使画面不变也调用 `oled_on()`。原生独立超时均禁用，扩展灯槽不增加六格任务页，细则见 [灯光兼容性](lighting-compatibility.md)。

- 屏幕为 128×32 单色，一帧 512 字节。所有画面强制保留左右至少 6 像素、上下至少 4 像素的黑边，不在最边沿绘制。
- 切到 L0/L1/L2 时，居中显示大号 `1/2/3`；这是显示编号，不改变 QMK/VIA 的 0/1/2 索引。
- 切到 L3 时，从首个未被休眠阻挡的渲染帧开始显示旧版终端图标 + `CODEX` 约 1 秒；有任务灯分配则进入六格状态页，无任务则持续显示 Logo。USB 挂起期间不消耗这段入层展示时间。
- 任务是否存在检查全部 0–12 槽的分配及非 off 状态，不看瞬时亮度/呼吸低点；B=0、黑色或速度 0 仍算任务。环境灯不算任务；全部任务明确 off 后回 Logo，不虚构任务结束语义。仅有扩展槽任务时仍显示原六格 `--`，不增加分页。
- 实际激活层计算包含默认层。切层清除旧按键提示，避免在新层显示上层内容。
- 原先通用的 `REQUESTED / NO LINK` 弹窗不再覆盖任务页。

## VIA 按键页

普通层从 USB 成功入队的输出报告取键值，而不是从物理位置或旧默认配置猜测。

- 6KRO/NKRO、普通键、修饰键组合、F1–F24、方向键、数字小键盘等显示实际 HID 键名。
- 例如 VIA 改成 ⌘C，屏幕显示 `GUI+C`；`GUI` 在 macOS 通常对应 ⌘，不是推断电脑最终执行的动作。
- 亮度、音量、媒体键、鼠标按键/移动/滚轮及普通层旋钮的输出也可显示。
- 双功能键按最终发送的键盘/消费报告显示；宏显示最近的实际输出键或组合，不显示固定的宏编号，也不逐字回放完整宏。
- 按键提示临时替换数字；按住时保留，全部松开或瞬时动作后约 900 ms 恢复居中层号。多路输入不因另一份空报告而提前变成空闲。
- 短提示居中一行，长组合最多两行，每行 19 个 ASCII 字符；过长内容截断，仍不贴边。
- 报告发送队列失败时不产生“已发出”的新提示。入队成功不等于操作系统或应用已确认处理。
- 不读取输入法转换、剪贴板或应用命令；无普通 HID 输出的层/RGB 动作只体现层切换，不虚构按键名。
- 输入提示只在 RAM 临时保留，不写 EEPROM、不保存按键日志、不需要电脑常驻程序。

## Codex 任务页

按物理 AG00–AG05 顺序，屏幕以 1–6 编号排成两行三列：

```text
 1:IDLE   2:RUN    3:NEW
 4:WAIT   5:ERR    6:--
```

| 标签 | 含义 |
|---|---|
| IDLE | 白色空闲 |
| RUN | 蓝色运行 |
| NEW | 绿色完成且未读 |
| WAIT | 橙色，等待回复/审批 |
| ERR | 红色错误 |
| -- | 未分配或灯效关闭 |
| OTHR | 宿主发送了其他基色 |

这些是现有 `v.oai.thstatus` 灯光槽推导的状态，不是任务标题、真实百分比、额度或逐字运行日志；任务改变后画面跟随更新。颜色语义仍可能随宿主版本变化。

## 验证与限制

- 十四组 OLED/报告测试覆盖留边、居中、Logo→任务页、无任务回 Logo、全灭/零亮度不关屏、首个可见帧完整一秒、六槽实时更新、6KRO/NKRO/宏报告、按住与空闲、媒体/鼠标、长组合、默认层、计时回绕及实际 ChibiOS 发送函数。
- 使用 QMK 的默认 ASCII 字体；不提供中文任务名称、彩色、GIF 或运行时图片上传。
- 只在画面变化时写入 OLED。USB 报告观察仅更新 RAM 文本，不在发送路径执行 I2C/OLED 绘制。
- 原始 Codex 图形复用旧上游位图；旧 NUMPAD/NAV/SYSTEM 功能名不恢复，避免 VIA 自定义后显示失真。
- 实机需核对物理遮边、切层停留、长按退出、VIA 改键后的提示、空闲恢复及任务变化；离线像素检查不替代目视验收。

可选导出合成测试画面（目录先创建，输出不含实机输入）：

```bash
mkdir -p /tmp/kb16-oled-previews
KB16_OLED_PREVIEWS=/tmp/kb16-oled-previews QMK_HOME=~/qmk_firmware \
  python3 firmware/keymaps/codex_micro_via_v1/tools/run_tests.py
```

每份 `.oled` 是 512 字节的页式单色帧，可用于检查边距和布局；不要把预览或构建产物提交到仓库。
