# DOIO KB16 Codex Micro 固件需求文档

> 当前版本 `0.6.0-qmk`：第一页 L0 为 Codex，L1–L3 普通 VIA；五处直接自定义，不再保留任何固定长按退出。10 秒 VIA 窗口及其他功能不变。已刷入对应提交的流水线 Artifact，版本应答确认 0.6.0-qmk、当前 Codex L0，以 v0.6.0-qmk Release 分发；[完整规则](codex-via-keys.md)。
> 硬件：DOIO KB16-01 Rev2，APM32F103CBT6，128 KB Flash / 20 KB RAM。
> 仓库只负责生成固件：QMK + VIA，不包含 Mapper；Git 不提交预编译产物，固件通过 GitHub Release 分发。

## 1. 项目目标与边界

- KB16 的 16 键、3 旋钮及 128×32 单色 OLED 提供 Codex Micro 兼容的原生控制，同时保留普通键盘改键。
- 使用 `firmware/keymaps/codex_micro_via_v1/` 和相应 QMK core patch；Rust/embassy、旧上游 keymap 仅作历史参考。
- 不需要额外常驻 host 程序；不做 Input 改键、`fs.*`、Mapper/Channel 3、AppSense/六层、触摸、无线或连续模拟摇杆。
- L0 只开放指定五处混用普通 VIA 动作，不允许 VIA 覆盖原生 Codex 键/旋转/C 按下；不提供运行时图片上传、彩色 OLED 或 GIF。
- 额度/任务标题同步需要额外程序，不纳入当前实现；旧可选方案仅作参考。

## 2. 四层与编辑语义

| 固件层 / VIA 页 | VIA 编辑保存 | 运行时 |
|---|---|---|
| L0 / 第一页 | 支持读写保存 | 仅五处 VIA 自定义执行，其余原生 Codex 固定 |
| L1 / 第二页 | 支持 | 普通动态键位/编码器 |
| L2 / 第三页 | 支持 | 普通动态键位/编码器 |
| L3 / 第四页 | 支持 | 普通动态键位/编码器 |

- 四层，`DYNAMIC_KEYMAP_LAYER_COUNT=4`、`POC_CODEX_LAYER=0`，无 L4。第一页原生 AG/ACT/旋转/C 按下不被 VIA 编辑覆盖。
- 五处全部走 QMK 正常流程，包括左上角；取消长按定时、短按重放和退出白光。切层由用户配置，建议 Codex `MO(1)` 临时普通 L1、松开返回；普通层 `TO(0)` 返回 Codex。
- 保留标准 MO 高层优先，不实现强制降层覆盖；普通透明键继承普通 L1，不能穿透到 Codex 原生控制，QMK 源层缓存保证跨层松开。
- 全新普通默认 B 按压为 L1→L2→L3→L0，Codex B 按下由 VIA 第一页自配，默认无动作。
- OLED、灯光及 RPC 状态包含默认层；`device.status.layer_index` 为 QMK 层 + 1，Codex 是 1。


## 3. 10 秒 VIA 窗口与 USB 身份

```text
上电
 ├─ 10 秒内收到有效 VIA 命令 → 锁定 VIA 身份直到断电
 └─ 无 VIA 命令 → 自动复位成 Codex 身份，默认 L0
       ├─ L1–L3 → 普通键盘 HID，读取保存的 VIA 改键
       └─ L0 → Codex 专用 HID，静态 AG/ACT/ENC/JOY
```

| | VIA 身份 | Codex 身份 |
|---|---|---|
| VID:PID | `D010:1601` | `303A:8360` |
| Raw HID | `FF60:0061`，32 字节，无 ID | `FF00:0001`，Report ID 6，64 字节 |
| 协议 | VIA 四页读写 | Codex Channel 2 JSON-RPC |

- 有效 VIA 命令包含协议版本查询；错误长度、未知 ID、越界层等不得锁定。
- VIA 连接后不自动切回 Codex，写入完成后断电重插才重新给窗口。
- 切层不改变 USB 身份；VIA 锁定时即便进入 L0，也不能向 Codex 发送可用专用事件。必须断电、不连 VIA，等窗口超时。
- 模式标志使用备份寄存器 `BKP->DR9`，保留 bootloader 的 `DR10`。
- USB 重枚举使用安全软复位；Codex 报告与 VIA 报告不混用。
- Raw HID 中断接收按报告边界分派；控制 SET_REPORT 入队，由主循环处理，不在中断内写 EEPROM 或解析 JSON。

## 4. Codex 固定键位与任务灯

L0 按 [键位对应](keymap.md) 实现：

- R1C2/R1C3/R2C1–R2C4 = AG00–AG05；R3C1–R3C4 = ACT06–ACT09。
- 第四行三个 ACT 右移：R4C1 = 直接 VIA5，R4C2/R4C3/R4C4 = ACT10/ACT11/ACT12。
- R1C1、R1C4、R4C1、A/B 按下为直接 VIA 自定义键，均可持续按住，无固定长按。旋转仍为摇杆 X/Y，C 仍为 Codex 编码器 CC/CW/Press。
- ACT10+ACT11 可由宿主合并为 MIC 或拆成两个动作；固件不改变宿主侧功能绑定。
- AG 事件不依赖是否收到任务灯分配；按下/松开配对。旋转每格只发送一次，按压保留按下/松开。
- `v.oai.thstatus` 驱动六个 AG，`v.oai.rgbcfg`/环境预览映射第四排全部四灯（VIA5、ACT10/ACT11/ACT12，LED 12–15），不只限 MIC 或录音。
- 原始 RGB 不改色；Idle 白色常亮为宿主亮度的 5%，普通常亮 100%，呼吸 0–100%，尊重全局亮度。
- AG 任意颜色 snake 转为原色 0–100%×宿主亮度呼吸，跟随宿主速度，0 暂停当前相位；白灰呼吸不叠加 Idle 常亮的 5%，不再固定 5 Hz。环境 snake 仍映射第四排四灯：蓝色类为 0–10%×宿主亮度同步呼吸，海绿色类例外常亮，其他颜色为 0–100% 呼吸；呼吸跟随宿主速度且 0 暂停，不用精确 RGB 白名单判断业务状态。
- ACT 无环境提示时默认灭、按住白光；第四排 ACT 的环境提示优先。两个顶部自定义方键无本地白光；左下 VIA5 仅跟随环境灯，不新增按住白光。环境提示不得覆盖六个 AG。
- 进入 L0 临时启用 Codex 灯光，离开恢复普通 RGB 开关/效果，不额外写 EEPROM。
- 固件灯槽支持 0–12，扩展 6–12 对应 ACT06–ACT12 物理灯，输入仍上报 ACT；任务灯态（含 B=0）优先于环境/按压，off 释放。现有 Cindy 只下发六路，十三路需宿主配套，不声称端到端已完成；OLED 原六格不变，映射及边界见 `lighting-compatibility.md`。
- OLED 在四层均仅受 USB 挂起/一小时无输入且无有效通信控制，不跟随宿主 RGB 全灭/B=0。RGB 在 L0 另受任务/环境聚合关灯条件控制，普通 VIA 层忽略 Codex 关灯状态。输入、有效心跳和重复报文均续时，不能仅在状态变化时续时；心跳不能推翻 RGB 的宿主明确关灯，呼吸低点不代表关灯。USB 挂起二者同灭，允许恢复时即使 OLED 帧不变也点亮；不清空灯态或改 EEPROM。完整优先级见 `lighting-compatibility.md`。
- 完整颜色、亮度和样式见 [灯光](lighting.md)。

## 5. OLED

- 冷启动十秒 VIA 等待期居中显示 `VIA WAITTING`，不显示 DOIO 启动页；收到 VIA 命令锁定后恢复普通页，无命令超时后进入 Codex 的 Logo+CODEX/任务页。使用实际模式窗口状态，不改变 USB/层或既有休眠策略。

- 128×32 单色，512 字节/帧；左右至少 6 px、上下至少 4 px 留黑，不贴屏幕边沿。
- 切到 L0 从首个可显示帧起展示旧终端图标+CODEX 约 1 秒，有任务灯分配时转六格状态，无任务时保留/恢复 Logo。检查全部 0–12 槽的分配及非 off 状态，B=0/黑色/暂停不算任务释放，环境灯不算任务；扩展槽不增加 OLED 分页。不新增宿主程序，不显示任务标题/额度或旧通用弹窗。
- VIA L1–L3 显示居中 1/2/3（对应编辑器第 2/3/4 页），包含默认层；成功入队的 USB 输出临时替换数字为实际键名/组合/媒体/鼠标，按住保留、松开约 900 ms 恢复层号。
- L0 五处自定义发出的普通 HID 输出也临时显示实际按键，优先于 Logo/任务页，松开约 900 ms 恢复；原生 Codex Raw HID 不产生普通键名，切层/RGB 等无普通输出的动作不伪造提示。
- 显示最终 6KRO/NKRO 等报告，而非旧默认键位；宏只显示最近输出，不获取输入法/应用最终文字，不保存输入历史。详见 `oled.md`。

## 6. 保存、迁移与安全

- 四页键位/encoder map 保存在 EEPROM，L1–L3 普通动态执行，L0 仅五处读取动态配置；其他 Codex 控制固定。无 Input/Mapper 第二套配置。
- 旧 L3→新 L0，旧 L0/L1/L2→新 L1/L2/L3；一次旋转键位和编码器，并转换 TO/MO/DF/PDF/TG/OSL/TT/LT/LM 目标。已有五处不再清空，宏不重写。
- 复用原 8 字节用户区标记，键位、encoder map、宏起址与容量不变。更早五层升级先处理旧 L4→旧 L3，再迁至新 L0；新默认带新标记，不重复迁移。
- 刷前导出配置；迁移需持续供电，不保证任意固件往返升级兼容。旧顺序 JSON 导入不自动重跑迁移，要自行调整页序与目标层。
- 提交/发布/刷写分别按用户授权执行；正式镜像由 Actions 构建；只支持 Rev2，只写应用区，不改 Bootloader/读保护，保留官方回退镜像。
- 不提交二进制产物，现有 Rust/embassy 历史目录不改。

## 8. 新版实机验收

1. 正常断电启动十秒等待；有效 VIA 命令锁定直到断电，无命令默认 Codex L0。
2. VIA 第 1 页仅五处执行，2–4 页普通配置均执行，原生 AG/ACT、旋转/C 按下不变。
3. 第一页左下设 MO(1)，按住时可按普通 L1 的键，松开回 Codex；跨层松开无卡键，TO(0) 可返回。
4. 两个左角及 A/B 按下均直接执行配置，按住超过一秒或更长没有强制退出；不再有退出白光。
5. 原有五处、普通键位/旋转和宏保留，层动作目标随页序调整，二次启动不重复迁移。
6. OLED 普通页 1/2/3、Codex Logo/任务页、自定义输出与约 900 ms 恢复均正常，边距保留。
7. 既定 AG/环境/扩展灯效果不变；一小时无输入且无有效通信时息屏，输入或有效报文唤醒，USB 挂起优先。
