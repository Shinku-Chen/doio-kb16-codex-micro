# v0.7.2-qmk · EEPROM 兼容修复

## 中文

仅适用 **DOIO KB16-01 Rev2 / APM32F103CBT6 / 128 KB Flash / Maple Bootloader**；不适用 Rev1（ATmega32U4）、无线版或其他同名硬件。

### 本次修复

- 0.7.2 是 EEPROM 兼容修复版本：此前 VIA 用 `QMK_BUILDDATE` 派生三字节 magic，跨编译日期刷机时会把仍存在的键位、encoder 和宏判为无效并恢复默认。0.7.2 改用固定 `KB` + schema 1 的 VIA 三字节 marker。
- 当前 schema 在 VIA 配置初始化路径原样保留键位、encoder、宏和布局选项，跨编译日期/固件版本保留，初始化路径只读不写；不宣称整个固件运行永不写 EEPROM。
- **从 0.7.1/更旧固件首次升级会恢复一次 VIA 默认（键位/encoder/宏/布局选项）并写当前 marker；请先导出 VIA 配置并保留回退镜像。** 旧日期 marker、旧 schema、未知/空白 EEPROM、全 FF、全 00 都按此规则恢复一次，第二次启动不再重置。
- **不迁移旧页序、自定义位置或旧层动作。** 旧顺序备份不能直接作为当前布局导入，需要自行转换或重新配置。
- 三字节只作格式标记校验，不是 payload CRC，不能保证检测到配置内容任意损坏；本版不追加 CRC 或新格式。
- 保留 `EECONFIG_USER_DATA_SIZE=8`、`POC_EEPROM_RESERVED_LAYER_SLOTS=5` 及键位/encoder/宏起址容量。`VIA_EEPROM_ALLOW_RESET` 保持原先未定义，不启用远程清空权限。
- 如果 QMK 全局有效标记本身也无效（例如首次使用的整片空白存储），原有 QMK 初始化仍会恢复全局设置；本版不额外重置 RGB 等全局设置，仅修复 VIA marker 校验路径。
- 保留 0.7.1 的逐键按住白光、Codex L0 取消一小时空闲关闭、普通 VIA L1–L3 一小时计时、USB 挂起全灭及其他既有运行行为。

### 升级与刷写

- **升级前必须导出 VIA 配置并保留官方回退镜像。** 从 0.7.1 或更旧固件第一次刷入 0.7.2 会清空一次 VIA 键位/encoder/宏/布局选项；同 schema 后续升级才保留。
- 本机 KB16-01 Rev2 需要拆开外壳，短按 PCB 内部 `RESET` 进入 Maple DFU；普通键和 VIA 切层不能代替硬件复位。
- 只允许 Maple alt 2 `Upload to Flash 0x8002000`，即应用区 `0x08002000`；不要写 Bootloader、修改读保护或做全片擦除。下载期间不要拔线；出现 `UNKNOWN` / `LIBUSB_ERROR_PIPE` 时停止并重新进入 DFU。
- 正式附件只由标签 `v0.7.2-qmk` 的 GitHub Actions 从源码测试、编译、校验并发布；不使用本地 BIN/HEX 上传，不覆盖旧标签或旧 Release 附件。附件应包含 BIN、HEX、VIA 定义、`BUILD-INFO.json` 和 `SHA256SUMS`；来源、源码提交、QMK/编译器版本和最终 SHA-256 以这些文件为准。

### 验收

- 开发验证：92 组固件回归（C 使用 ASan/UBSan）、13 项打包测试、本地 ARM QMK 编译、BIN 应用区/DFU CRC/双 USB 描述符及 BIN/HEX 一致性检查通过。流水线会重新执行这些检查；CI 不刷硬件。
- **正式 `0.7.2-qmk` 尚未刷入。** 白光功能验收来自 `db2cdf1` 同逻辑流水线开发镜像（版本字符串仍为 `0.7.0-qmk`）；0.7.2 的 EEPROM 修复只有宿主/流水线验证，未做实机 EEPROM 掉电、Flash 读回或刷写验收。普通 VIA 层灯光、真实长时间空闲和光度测量仍未验收。

## English

Only for **DOIO KB16-01 Rev2 / APM32F103CBT6 / 128 KB Flash / Maple Bootloader**. Not for Rev1 (ATmega32U4), wireless variants or other similarly named hardware.

### Fix

- 0.7.2 is an EEPROM compatibility bugfix. Previously VIA derived its three-byte magic from `QMK_BUILDDATE`, so flashing firmware built on a different date could treat existing keymaps, encoders and macros as invalid and restore defaults. 0.7.2 uses a fixed `KB` + schema 1 VIA marker instead.
- The current schema preserves keymaps, encoders, macros and layout options in the VIA configuration initialization path across build dates/firmware versions, and is read-only there; this does not claim the whole firmware never writes EEPROM.
- **The first upgrade from 0.7.1 or older restores VIA defaults once (keymap/encoders/macros/layout options) and writes the current marker; export your VIA configuration and retain a recovery image first.** Old date markers, old schemas, unknown/blank EEPROM, all-FF and all-00 follow the same one-time reset; later boots do not reset again.
- **No migration of old page order, custom positions or layer actions.** Old-order backups cannot be imported directly as the current layout; convert or reconfigure them manually.
- The three bytes validate the format marker only. They are not a payload CRC and cannot guarantee detection of arbitrary configuration corruption; no CRC or new format is added.
- `EECONFIG_USER_DATA_SIZE=8`, `POC_EEPROM_RESERVED_LAYER_SLOTS=5` and the keymap/encoder/macro addresses and capacity are unchanged. `VIA_EEPROM_ALLOW_RESET` remains undefined as before; remote-clear permission is not enabled.
- If QMK's own global validity marker is also invalid (for example a blank first-use EEPROM), QMK's original initialization still restores global settings. This release does not add an extra RGB/global reset; it only fixes the VIA marker validation path.
- Retains 0.7.1 per-key held white, no Codex L0 one-hour idle timeout, ordinary VIA L1–L3 one-hour timer, all-layer USB-suspend off and other existing runtime behavior.

### Upgrade and flashing

- **Export the VIA configuration and retain an official recovery image before upgrading.** The first flash from 0.7.1 or older to 0.7.2 clears VIA keymaps/encoders/macros/layout options once; later same-schema upgrades preserve them.
- This KB16-01 Rev2 requires opening the case and briefly pressing the PCB's internal `RESET` to enter Maple DFU; ordinary keys and VIA layer actions cannot replace hardware reset.
- Write only Maple alt 2 `Upload to Flash 0x8002000`, the `0x08002000` application area. Never write the bootloader, change read protection or mass-erase. Do not disconnect during download; stop and re-enter DFU on `UNKNOWN` / `LIBUSB_ERROR_PIPE`.
- Official assets are built, tested and published only by GitHub Actions from tag `v0.7.2-qmk`; no local BIN/HEX uploads, and existing tags or Release assets are not overwritten. Expect BIN, HEX, the VIA definition, `BUILD-INFO.json` and `SHA256SUMS`; verify source commit, QMK/compiler versions and final SHA-256 values in those files.

### Acceptance

- Development validation passed: 92 firmware regression groups (ASan/UBSan), 13 packaging tests, local Arm QMK compilation, BIN application-area/DFU CRC/dual USB descriptor checks and BIN/HEX equivalence. The workflow repeats these checks; CI never flashes hardware.
- **The official `0.7.2-qmk` has not been flashed.** Press-white acceptance comes from the `db2cdf1` pipeline development image (version string still `0.7.0-qmk`). The 0.7.2 EEPROM fix is host/pipeline validated only; no hardware EEPROM power-loss, Flash readback or flashing acceptance was performed. Ordinary VIA lighting, prolonged idle and photometric measurements remain unverified.
