# v0.7.1-qmk · 逐键按住白光 / Codex 取消空闲关闭

## 中文

仅适用 **DOIO KB16-01 Rev2 / APM32F103CBT6 / 128 KB Flash / Maple Bootloader**；不适用 Rev1（ATmega32U4）、无线版或其他同名硬件。刷写前先导出 VIA 配置并保留官方回退镜像；不要擦写 Bootloader 或更改读保护。

### 两项行为

- **Codex L0 全部 16 个方键逐键按住白光**：按住哪个方键，仅对应物理 LED 显示 100% 纯白；多键分别叠加。该本地反馈优先级高于任务灯、第四排环境灯和宿主软件关灯，松开后恢复最新宿主灯态或熄灭。三个旋钮没有独立按键 LED，不增加白光；普通 VIA L1–L3 不新增按压白光。
- **Codex L0 取消 RGB/OLED 一小时空闲关闭**：长时间无输入、心跳或灯态更新时，RGB 保持宿主最后下发状态，OLED 保留 Logo/任务页。普通 VIA L1–L3 仍保留一小时无输入且无有效通信后关闭 RGB/OLED；按键输入、有效心跳、完整重复灯态及有效 VIA 命令都会续时。USB 挂起时所有层 RGB/OLED 同时关闭；恢复后仍按当前层策略。宿主明确关灯优先于背景灯，但按住白光可在按住期间临时覆盖，松开后仍遵循宿主关灯状态。
- 保留四层、L0 VIA 优先/空键回退、L1–L3 普通 VIA、十秒 `VIA WAITTING` 身份协商、已有键位/宏/EEPROM 地址和历史迁移。`0.7.0` → `0.7.1` 不新增迁移、不清空配置；与已测 `db2cdf1` 开发镜像相比，本次发布准备仅更新版本 metadata 和文档；相较旧正式 `0.7.0-qmk`，新增上述两项行为。

### 刷写与回退

- 本机 KB16-01 Rev2 需要拆开外壳，短按 PCB 内部 `RESET` 进入 Maple DFU；普通键和 VIA 切层不能代替硬件复位。
- 只允许 Maple alt 2 `Upload to Flash 0x8002000`，即应用区 `0x08002000`；不要写 Bootloader、修改读保护或做全片擦除。下载期间不要拔线；出现 `UNKNOWN` / `LIBUSB_ERROR_PIPE` 时停止并重新进入 DFU。
- 先导出 VIA 配置并保留可用的官方回退镜像。升级不会清空现有配置，但仍应检查 L0 按键/旋钮和层动作目标后再刷。

### 产物与验收

- 正式附件只由标签 `v0.7.1-qmk` 的 GitHub Actions 从源码测试、编译、校验并发布；不使用本地 BIN/HEX 上传，不覆盖旧标签或旧 Release 附件。附件应包含 BIN、HEX、VIA 定义、`BUILD-INFO.json` 和 `SHA256SUMS`；来源、源码提交、QMK/编译器版本和最终 SHA-256 以 `BUILD-INFO.json` / `SHA256SUMS` 为准。
- 开发验证：80 组固件回归（C 使用 ASan/UBSan）、13 项打包测试、本地 ARM QMK 编译、BIN 应用区/DFU CRC/双 USB 描述符及 BIN/HEX 一致性检查通过。流水线会重新执行这些检查；CI 不刷硬件。
- 2026-11-04 用户确认“按下白光”功能正常，针对功能分支 `db2cdf1` 的流水线开发镜像（版本字符串仍为 `0.7.0-qmk`，BIN 51,320 字节，SHA-256 `d1d9aa2153623b5c15f166536b851587677fcdcae76e84a6a14688d6687e09e3`）。全部方键与多键叠加已有软件回归覆盖，但不据此声称完成逐键光度测量或所有功能的实机验收。
- **正式 `0.7.1-qmk` 未再次刷入**；本次发布准备相对已测 `db2cdf1` 只更新版本/文档，不能写成 0.7.1 已实机刷过。普通 VIA 层不新增白光、普通层灯光、真实长时间无空闲关闭、USB 挂起/OLED 目视的逐项复测及 Flash 读回仍未验收；不能从白光确认外推这些项目。

## English

Only for **DOIO KB16-01 Rev2 / APM32F103CBT6 / 128 KB Flash / Maple Bootloader**. Not for Rev1 (ATmega32U4), wireless variants or other similarly named hardware. Export your VIA layout and retain an official recovery image before flashing; never overwrite the bootloader or change read protection.

### Two behavior changes

- **Per-key press white on all 16 Codex L0 square keys**: holding a square key lights only its corresponding physical LED at 100% pure white; multiple held keys stack. This local feedback has higher priority than task lights, fourth-row ambient lighting and host software all-off, and release restores the latest host lighting state or off. The three knobs have no independent key LED and add no white; ordinary VIA L1–L3 add no press white.
- **No one-hour RGB/OLED idle timeout on Codex L0**: with no input, heartbeat or lighting update for a long time, RGB retains the last host state and OLED keeps the logo/task page. Ordinary VIA L1–L3 still turn RGB/OLED off after one hour without input or valid communication; key input, valid heartbeats, complete repeated lighting frames and valid VIA commands renew the timer. USB suspend turns RGB/OLED off on every layer; after resume the active layer's policy applies. An explicit host all-off still turns the background off, but held white may override it while the key is held and the host off state returns on release.
- Four layers, L0 VIA priority/native fallback, L1–L3 ordinary VIA, the ten-second `VIA WAITTING` identity handshake, existing keys/macros/EEPROM addresses and historical migrations are retained. `0.7.0` → `0.7.1` adds no migration and clears no configuration; release preparation changes only metadata and documentation relative to the tested `db2cdf1` development image; compared with the old official `0.7.0-qmk`, it includes the two behavior changes above.

### Flashing and recovery

- This KB16-01 Rev2 requires opening the case and briefly pressing the PCB's internal `RESET` to enter Maple DFU; ordinary keys and VIA layer actions cannot replace hardware reset.
- Write only Maple alt 2 `Upload to Flash 0x8002000`, the `0x08002000` application area. Never write the bootloader, change read protection or mass-erase. Do not disconnect during download; stop and re-enter DFU on `UNKNOWN` / `LIBUSB_ERROR_PIPE`.
- Export the VIA layout and retain a usable official recovery image first. Upgrading does not clear existing configuration, but inspect L0 keys/knobs and layer-action targets before flashing.

### Assets and acceptance

- Official assets are built, tested and published only by GitHub Actions from tag `v0.7.1-qmk`; no local BIN/HEX uploads, and existing tags or Release assets are not overwritten. Expect BIN, HEX, the VIA definition, `BUILD-INFO.json` and `SHA256SUMS`; verify source commit, QMK/compiler versions and final SHA-256 values in those files.
- Development validation passed: 80 firmware regression groups (ASan/UBSan), 13 packaging tests, local Arm QMK compilation, BIN application-area/DFU CRC/dual USB descriptor checks and BIN/HEX equivalence. The workflow repeats these checks; CI never flashes hardware.
- On 2026-11-04 the user confirmed press-white functionality on the `db2cdf1` pipeline development image (still reporting `0.7.0-qmk`, BIN 51,320 bytes, SHA-256 `d1d9aa2153623b5c15f166536b851587677fcdcae76e84a6a14688d6687e09e3`). Software regression covers all square keys and multi-key stacking; the visual confirmation is not a claim of per-key photometric measurements or complete hardware acceptance.
- **The official `0.7.1-qmk` image has not been flashed again.** Release preparation changes only version/documentation relative to the tested `db2cdf1` image and must not be described as hardware-tested 0.7.1. Ordinary VIA layers add no white; ordinary-layer lighting, prolonged no-timeout behavior, per-item USB-suspend/OLED visual retests and Flash readback remain unverified and must not be inferred from the white acceptance.
