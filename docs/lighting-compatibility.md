# 灯光下发完整性与必要性评估

## 本轮范围

2026-10-30 用户将休眠定为 VIA 空闲一小时关闭，Codex 跟随下发并有一小时兜底，心跳及重复报文均续时；规则来自 `0.4.6-qmk`。已刷 `0.4.7-qmk` 用户反馈正常。当前源码 `0.4.8-qmk` 仅改 10 秒启动、1 秒退出，未刷入，不改变本页语义；一小时实机时序及十三路宿主配套仍不能视为已验收。

## OLED 与背光休眠

| 当前层 | 宿主控制 | 一小时兜底 |
|---|---|---|
| VIA L0–L2 | 保留普通 QMK 背光，不使用 Codex 全局关灯状态 | 按键/旋钮或有效通信续时；连续一小时无活动，RGB/OLED 一起关闭 |
| Codex L3 | 全部受支持任务灯和环境灯为 off/零亮度/不会发光的黑色时一起关闭，任一组恢复则点亮 | 同样按输入和有效通信续时，连续一小时无活动一起关闭 |

- 用户已纠正：心跳和内容完全相同的重复报文也要重置一小时，不能仅在灯态改变时续时。完整且有 method 的宿主 RPC（包括 sys.version/device.status、重复灯态）及有效 VIA 命令计为活动；坏帧/无 method 不计。按键/旋钮使用 QMK 的同一输入活动时钟；动画自身运行和 OLED 刷帧不是活动。
- 一小时门限为 `POC_IDLE_SLEEP_MS=3600000UL`，恰好达到时关闭。`poc_power_should_sleep()` 同时控制 RGB 指示器最终输出和 OLED；`RGB_MATRIX_TIMEOUT/OLED_TIMEOUT=0` 仅禁用两套原生独立计时器，并不代表没有一小时兜底，防止它们绕过心跳续时提前关灯。
- Codex 只根据保存的 c/b/e/s 聚合判断，不依据当前 PWM 像素：呼吸低点不息屏，黑色基色的 rainbow/gradient 仍视作可发光。关掉一个任务或一组环境灯，不会关闭仍有其他亮灯状态的 OLED；keys/backlight 尚未渲染，不作为该聚合的虚假亮灯来源。
- 尚未收到有效灯态前，保留现有 Logo/任务页，仍受一小时兜底限制。宿主自身不完整更新留下的旧灯态继续参与聚合，不假装知道未下发的业务状态。
- 优先级是 USB 挂起、Codex 明确全局关灯、一小时兜底、原灯光规则。宿主明确关灯后，心跳只续时、不重新点亮，本地 ACT/切层白光也被屏蔽；按键仍正常上报，一秒退出可切回 VIA。宿主再发可发光的状态才恢复；仅因空闲兜底关闭时，输入或有效报文即可唤醒并恢复原灯态。
- USB 挂起二者同灭，恢复时仍检查上述策略。恢复允许点亮时，即使 OLED 帧缓存没变化也调用 `oled_on()`。休眠不清空灯态、不改 EEPROM、颜色或亮度；OLED 本身仍为单色，不声称能跟随 RGB 的颜色/亮度。

## 六路之外的任务灯

固件接收 `v.oai.thstatus` 灯槽 id 0–12，保持原生 HID 输入；宿主必须按下表的物理键编号投影任务状态，不能直接将自定义任务列表顺序视为灯位。空位与切层键保留，因此本次是 13 个任务灯，不是 16 个。

| 灯槽 id | 物理输入名称 | KB16 位置 | LED |
|---|---|---|---|
| 0 / 1 | AG00 / AG01 | R1C2 / R1C3 | 1 / 2 |
| 2 / 3 / 4 / 5 | AG02 / AG03 / AG04 / AG05 | 第二排四键 | 4 / 5 / 6 / 7 |
| 6 / 7 / 8 / 9 | ACT06 / ACT07 / ACT08 / ACT09 | 第三排四键 | 8 / 9 / 10 / 11 |
| 10 / 11 / 12 | ACT10 / ACT11 / ACT12 | R4C2 / R4C3 / R4C4 | 13 / 14 / 15 |

- 六个原生 AG 不变；其他七键仅在收到对应非 off 的任务灯态后，使用任务灯渲染，沿用原色、Idle 常亮 5% 和 snake 转呼吸等规则。
- 扩展任务灯优先于 ACT 按压白光和第四排环境灯。任务 B=0 仍占有该灯位并保持黑色；下发 e=off 才释放，恢复原先的环境/按压反馈。左下角切层键不在扩展灯槽中，其按住白光和一秒退出不变。
- 仍上报 ACT06–ACT12，不自动改成 AG06–AG12，不要求 Input/Mapper，不改变普通 VIA 层。仅有 ACT 输入的软件任务绑定，不代表宿主已经向对应灯下发状态。
- OLED 保留现有六格任务页，只显示 id 0–5；扩展灯槽不直接增加绘制循环，避免截断或越出 128×32 边距。更多任务的分页显示不在本轮范围。
- RPC 重组从 1024 扩为 2048 字节，覆盖十三槽带 SDK 浮点文本/同步字段的完整帧；越界 id 不写数组。2048 是有限上限，不支持任意大的批量请求。

### Cindy 端已确认的边界

只读检查本机 `/Applications/Cindy.app/Contents/Resources/cindy-source.json`，其 sourceCommit 为 `b3dd8436228135aa8be9827d204e4e5eaf9316b4`。该提交不能从临时参考仓库取回，因此改为直接检查已安装 `app.asar` 的 `.vite/build/bootstrap-electron-BQG0kPOv.js`，没有修改应用文件。

打包代码中的 `WORKLOUDER_CODEX_AGENT_SLOT_COUNT=6`，`lightingThreadCount()` 返回该常量。Cindy 允许 ACT 充当额外任务入口，但当前灯态只为六个原生 AG 物理键生成；它也会在自定义任务布局下静音共享 keys 灯区。SDK 的 `sendThreadsLighting()` 会原样保留调用方传入的 id 并最小化为 c/b/e/s/sk/sa，瓶颈是宿主生成的灯态数量与物理映射，不是给固件数组扩容就能解决。

因此，本版只是准备好 KB16 固件的扩展接收和渲染。要让 Cindy 第 7–13 个任务实际独立亮灯，仍需在宿主为这套固件生成十三路物理键灯态，并正确释放降为普通 ACT 的旧任务灯槽；不能把本轮离线测试称为 Cindy 十三路端到端验收。没有用户进一步要求时，不修改 Cindy 源码或已安装应用。

## 其他未完整实现内容是否必要

| 项目 | 必要性 | 本轮处理与理由 |
|---|---|---|
| OLED 独立超时 | 已修复并更新规则 | 两者共用一小时兜底，心跳/重复通信续时；Codex 全部灯态关闭时同步关闭 OLED，USB 挂起优先 |
| 第 7–13 路任务灯 | 用户明确需要 | 补齐固件、物理灯映射、优先级和帧容量；Cindy 仍需配套下发 |
| 省略 effect 意外恢复点灯 | 必须修复 | SDK 明确其他字段可选，省略表示保持；现在 off 不会因局部颜色/亮度/速度更新或空对象自动变 solid |
| rgbcfg.keys / preview.backlight | 可选，默认不应直接开启 | 这是共享整组背光，不是 ACT 单键任务灯；直接应用会改变“普通 ACT 默认灭、按住亮”的要求。十三路独立任务灯不依赖铺满 keys 背景 |
| sk/sa 同步字段 | 暂不优先 | SDK 说明其让 keys/ambient 跟随某任务的 RGB；已安装 Cindy 灯帧均传 false。实现还需确定多个同步任务的优先级，并避免覆盖保留的环境规则，不能靠猜测实现 |
| m/magic | 暂不实现行为 | 当前宿主通常传 0，SDK 未给出非零值的可执行含义；OpenMicroKbd 也标记为 unused，不应臆造灯效 |
| gradient 与 rainbow 区分 | 低优先级 | 目前共用算法，OpenMicroKbd 参考也如此；SDK 对两者描述不同，但缺少原厂逐帧定义。常规任务帧不依赖它们，不能据同算法就宣称全部兼容或确定错误 |
| 未知效果保持旧值却返回 ok | 建议后续补诊断 | 合法宿主请求不受影响，但无效参数反馈不充分；需区分新字段兼容与真正非法参数，不能一律拒绝扩展 |
| 科学计数法等完整 JSON 数值解析 | 建议后续补齐 | 当前解析不是完整 JSON 数值实现，极小浮点值可能以指数形式序列化而被误读；常见现有亮度值回放已覆盖，不应承诺任意数值都正确 |
| 宿主静默兜底关灯 | 用户已明确要求 | 一小时无输入且无有效通信即关闭；心跳/重复帧均续时。它是空闲保护，不宣称精确识别宿主断联 |

keys/backlight、同步字段等仍可能被确认成功却未执行全部含义，本次没有将它们改成“完整支持”。AG snake 转原色呼吸、Idle 常亮 5% 和第四排微调仍属于用户确认的输出例外，不是原厂动效逐帧复刻。

## 验证边界

60 项离线检查包含原十三槽/灯效/共享休眠覆盖和新增启动等待、板级 Logo 绕过、屏幕文字/边距检查。共享策略覆盖一小时边界、四层切换、输入及心跳/重复报文续时、静默后唤醒、USB 挂起及回绕，真实 RPC/VIA/RGB/OLED 路径均测试；硬件/USB 使用桩，不等于实机睡眠、冷启动画面或 Cindy 十三路已验收。实机已确认运行 `0.4.7-qmk`；刷写记录及哈希见 [开发与构建](development.md)。
